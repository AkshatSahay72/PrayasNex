# Adaptive Learning Platform --- Prototype Instructions

## 1. Purpose

This repository is the **working prototype** of an Adaptive Learning
Platform.

The goal is not to build the complete production platform yet.

The goal is to build **one small, complete, demonstrable end-to-end
system** that proves the main idea:

> The system observes a student's performance at the concept level and
> uses that evidence to recommend what the student should learn or
> practice next.

The prototype must be simple enough for an instructor to understand and
run, but its internal structure should be clean enough that it can later
be expanded into the full project.

Do not add enterprise-level complexity just to make the project look
advanced.

------------------------------------------------------------------------

# 2. Prototype Scope

The prototype must implement this flow:

``` text
Student
   ↓
Select Subject / Topic
   ↓
Study Concept
   ↓
Take Concept-Based MCQ Test
   ↓
Submit Answers
   ↓
Evaluate Performance
   ↓
Calculate Concept Performance
   ↓
Identify Weak Concept
   ↓
Generate / Show Personalized Note
   ↓
Recommend Next Learning Activity
```

A complete demo should work from beginning to end without requiring
manual database editing.

# 3. What the Prototype Must Demonstrate

The instructor should be able to see these capabilities:

### A. Concept-based learning

Questions are attached to concepts rather than existing as unrelated
random questions.

Example:

``` text
Machine Learning
└── Optimization
    ├── Gradient
    ├── Learning Rate
    └── Gradient Descent
```

### B. Student performance tracking

The system records:

-   selected answer
-   correctness
-   concept
-   attempt
-   score
-   basic learning history

### C. Weak-concept detection

The system identifies concepts where the student is struggling.

For the prototype, simple deterministic rules are enough.

Example:

``` text
0–49%  → Weak
50–79% → Needs Practice
80–100% → Strong
```

These thresholds are prototype rules, not the final adaptive-learning
algorithm.

### D. Adaptive recommendation

The system recommends the next action based on the student's
performance.

Example:

``` text
Weak
  ↓
Review concept
  ↓
Practice again
```

``` text
Strong
  ↓
Move toward next concept
```

### E. Personalized learning note

When a concept is weak, the system should show a short explanation
targeted to that concept.

The note may be generated by an LLM, but the application must remain
functional even if the AI provider is unavailable.

### F. Question quality validation

AI-generated questions must not be blindly displayed.

The prototype should validate:

-   valid JSON structure
-   exactly one correct answer
-   relevant distractors
-   no obviously unrelated option
-   reasonable option length
-   concept/topic match
-   requested difficulty

The validation does not need to be a research-grade semantic evaluator
in V1.

# 9. Assessment Security

During an active test, the frontend must NOT receive the correct answer.

Bad:

``` json
{
  "question": "...",
  "options": ["A", "B", "C", "D"],
  "correct_option": "B"
}
```

Good:

``` json
{
  "question_id": "q123",
  "question": "...",
  "options": ["A", "B", "C", "D"]
}
```

The backend should evaluate the submitted answer.

------------------------------------------------------------------------

# 10. Adaptive Logic

The prototype does not need machine learning to decide what to
recommend.

Use deterministic rules.

Example:

``` text
score < 50%
    → weak
    → recommend review

50%–79%
    → needs practice
    → recommend more questions

80%+
    → strong
    → recommend next concept
```

If prerequisite information is available:

``` text
Weak concept
    ↓
Check prerequisite
    ↓
If prerequisite is weak
    → recommend prerequisite first
```

Keep this logic in backend/adaptive service code, not in the React
frontend.

------------------------------------------------------------------------

# 11. AI Question Pipeline

Never do:

``` text
LLM → database → student
```

Use:

``` text
LLM
 ↓
Parse structured response
 ↓
Schema validation
 ↓
Rule validation
 ↓
Valid?
 ├── YES → save
 └── NO → reject / retry
```

The prototype should specifically protect against the known ExamBuddy
problems:

### Problem 1 --- Correct option is much longer

Do not allow an option to become an obvious answer clue.

### Problem 2 --- Irrelevant distractors

Every wrong answer should belong to the same conceptual neighborhood.

### Problem 3 --- Absurd distractors

Avoid obviously nonsensical options.

### Problem 4 --- Multiple correct answers

Reject questions where more than one option can reasonably be defended.

### Problem 5 --- Topic mismatch

A question requested for Gradient Descent should actually test Gradient
Descent.

### Problem 6 --- Difficulty mismatch

A beginner question should not secretly require advanced knowledge.

------------------------------------------------------------------------

# 12. AI Failure Handling

The application must remain usable if the AI API fails.

Use this fallback order:

``` text
Existing validated question
        ↓
Cached/generated content
        ↓
AI generation
        ↓
If AI fails:
use existing content / show controlled error
```

Do not make the entire application dependent on a successful AI request.

# 14. Prototype User Flow

A successful demonstration should work like this:

``` text
1. Open application
2. Select Machine Learning
3. Select Optimization
4. Open a concept
5. Read the learning note
6. Start test
7. Answer 5 questions
8. Submit
9. Backend evaluates answers
10. Backend updates progress
11. System identifies weak concept
12. System generates/selects personalized note
13. System recommends next activity
14. Dashboard reflects the updated state
```

This complete flow is more important than having many features.

------------------------------------------------------------------------

# 15. Definition of Done

The prototype is complete when:

-   application starts successfully
-   frontend communicates with backend
-   database initializes
-   subjects/topics/concepts can be loaded
-   questions can be displayed
-   student can submit answers
-   backend evaluates answers
-   attempts are stored
-   concept performance is calculated
-   weak concept is identified
-   recommendation is produced
-   personalized note can be displayed
-   AI-generated questions are validated before use
-   application still works when AI generation fails
-   no correct answer is exposed before submission
-   README explains how to run the project
-   there is at least basic backend testing
-   the complete demo flow works without manual database manipulation
